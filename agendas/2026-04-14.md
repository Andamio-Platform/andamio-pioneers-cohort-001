## 4. Feedback: Why is it safe to vibe code an Andamio app?

No new issues in the pioneers repo since meeting #07.

Live feedback is landing on the [Reddit XP thread](https://www.reddit.com/r/cardano/comments/1sgoe93/) — 5.4K views, 34 upvotes, 15 comments. Worth walking through together:

- **Dreamstride** — site broken, save button missing → diagnosed + fixed
- **PM_ME_UR_0_DAY** — pentested with a scary token name → credential approved, "resident security expert"
- **marcecostai** — vibe-code concern → sharpened today's framing (section 3)
- **BreakfastIll5533** — "Stack Overflow tailored for Cardano... 'earned then given' is a smart way to prevent gaming" + asked: *how do you handle human review at scale?*

One comment raised a key concern:

> "Vibe coded app, no way I'm connecting my wallet to that, gl." — marcecostai

The Andamio API is not vibe coded. That layer is audited, versioned, reviewed. What *is* vibe coded is the UX on top — and that's the point. Once the protocol primitives exist, apps like Cardano XP can ship quickly because the safety-critical work (auth, credentials, access tokens, on-chain settlement) is already handled below.

| Layer | Built by | Quality bar |
|-------|----------|-------------|
| Protocol | Andamio core team | Audited, versioned |
| App surface | Anyone — vibe coders welcome | Iterates on user feedback |

Cardano XP is the live proof: a single Sunday afternoon, on mainnet, taking real feedback.

**Question for the room:** does this framing land? Worth calling out explicitly in new-developer onboarding?
